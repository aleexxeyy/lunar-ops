# Lunar Ops

Навчальний тренажер місячної місії для Junior Astronaut Mission Trainer / NASA Space Apps Challenge 2026. Український інтерфейс командного термінала: адаптивна схема станції, ресурси, операції, екіпаж, події та журнал.

## Запуск

Потрібні Node.js 24 та pnpm 11.25.0.

```sh
pnpm install
pnpm dev
```

Відкрийте адресу Vite (зазвичай http://localhost:5173). API запускається на порту 3000; Vite проксіює `/api`. Для розгортання потрібен такий самий зворотний проксі. Інтерфейс працює зі справжнім API: за відсутності зв’язку показує помилку та кнопку повторного підключення.

## Місія

Збережіть екіпаж протягом 7 ігрових днів і здобудьте 60 наукових балів. На день доступні дві операції; кожну звичайну операцію можна виконати один раз. Поліпшення модуля також витрачає операцію. Ролі екіпажу змінюються безкоштовно, а бонуси діють наприкінці дня. Події потребують рішення перед продовженням. Є рівні «Кадет» і «Командир».

Дні, відсотки ресурсів і події — умовна навчальна модель без оперативних даних NASA. Баланс і сценарії містяться в `packages/game-config`.

## Архітектура

- `apps/web`: React, Zustand, Tailwind, Recharts, Framer Motion; лише відображення та надсилання команд.
- `apps/api`: NestJS, перевірка команд через Zod, зберігання остаточного стану сесій у пам’яті сервера.
- `packages/contracts`: спільні типи та схеми вхідних запитів.
- `packages/game-core`: детермінована симуляція, доступність дій, витрати, виробництво, події, перемога та евакуація.
- `packages/game-config`: баланс, ролі, модулі, сценарії.

У браузері зберігається лише ідентифікатор сесії. Оновлення сторінки відновлює стан через API. Перезапуск API скидає сесії; інтерфейс повідомляє про це та створює нову. Бази даних і авторизації немає. Перевірка `revision` запобігає повторному застосуванню застарілих команд з інших вкладок.

## Перевірки

```sh
pnpm build
pnpm typecheck
pnpm test
pnpm --filter @lunar-ops/api test:e2e
pnpm --filter @lunar-ops/web test:e2e
```

Playwright використовує встановлений Google Chrome; для Edge задайте `PLAYWRIGHT_CHANNEL=msedge`. Перед браузерними тестами виконайте `pnpm build`. Перевіряються версії для комп’ютерів і телефонів, навігація, діалоги, поліпшення, ролі, експорт, відновлення зв’язку, нова місія та повне проходження до перемоги.

Тести запускають окремі екземпляри API (порт 3100) та Vite (5174), не використовуючи сервер розробки та його сесії. Порти мають бути вільними. `LUNAR_API_URL` задає адресу API для проксі Vite; без змінної використовується порт 3000.

Розділи мають адреси `#/overview`, `#/station`, `#/crew`, `#/journal`: працюють оновлення сторінки та історія браузера. Картки ресурсів відкривають телеметрію, відповідну операцію відновлення та модуль бази. Усі чотири модулі доступні зі схеми станції.

За відсутності зв’язку ігрові команди блокуються до повторного підключення; переглядати останній стан можна. Якщо відповідь на вже виконану команду втрачено, клієнт запитує актуальний стан без повторного списання ресурсів. Конфлікт версій із різних вкладок оновлює дані та повідомляє про відхилену команду. Відновлення повністю заповнених запасів не витрачає операції.

Браузерні перевірки охоплюють усі групи кнопок, графіки, обидва рівні складності, перемогу та евакуацію, завантаження вмісту JSON, подвійне натискання, втрачену відповідь, конфлікт вкладок і вимкнене сховище браузера. Браузерні тести також входять до перевірки TypeScript.
